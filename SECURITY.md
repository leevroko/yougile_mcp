# SECURITY: План переработки безопасности yougile-mcp

> План утверждается до реализации. Результат: credentials вне environment, контроль мутаций пользователем, аудит всех изменений.
> Статус: ✅ **реализовано** (фазы 1–4, коммит после финального ревью).

---

## 0. Модель угроз (локальная машина, один пользователь, stdio)

| # | Угроза | Вектор | Серьёзность |
|---|--------|--------|-------------|
| T1 | **Утечка API-ключа** | env виден всем процессам пользователя; транскрипты сессий (echo/env в логах); дочерние процессы | 🔴 высокая — **произошёл инцидент**: часть ключа (44+ из 64 симв.) попала в транскрипт при отладке |
| T2 | **Непреднамеренные мутации LLM** | агент вызывает create/update/bulk без подтверждения (в E2E pi сам создал задачу на живой доске) | 🔴 высокая |
| T3 | **Отсутствие следов мутаций** | никто не узнает, что/когда менял агент | 🟡 средняя |
| T4 | **Некорректные метаданные инструментов** | все 15 инструментов помечены как destructive → клиенты не могут различать чтение/запись | 🟡 средняя |

**Вне области** (осознанно): сетевые атаки (нет сетевой поверхности — только stdio), многопользовательский доступ, доступ другого пользователя ОС к `/proc` (считаем машину доверенной для одного пользователя).

## 1. Фаза 1 — Credentials вне environment

### Хранение

Файл `~/.config/yougile-mcp/config.json`:

```json
{
  "api_key": "T01...",
  "base_url": "https://ru.yougile.com/api-v2",
  "memory_dir": "~/.local/share/yougile-mcp/memory/reviews",
  "read_only": false,
  "permissions": {
    "allow":   ["list_*", "get_*", "get_board_snapshot", "summarize_board", "track_goals", "compress_reviews"],
    "confirm": ["create_task", "update_task", "audit_board", "bulk_move_tasks", "batch_update_stickers"],
    "deny":    []
  },
  "audit": {
    "enabled": true,
    "path": "~/.local/state/yougile-mcp/audit.jsonl"
  }
}
```

Требования к правам: каталог `~/.config/yougile-mcp/` — `700`, файл — `600`. При нарушении сервер **отказывается стартовать** с понятным сообщением (override: `"allow_insecure": true`).

### Загрузка (порядок приоритета)

1. Флаг `--config /path` (CLI)
2. `YOUGILE_CONFIG=/path` — env содержит **только путь, не секрет**
3. Дефолт `~/.config/yougile-mcp/config.json`

`YOUGILE_API_KEY` как источник секрета **удаляется**. Конфиг читают оба компонента:
- Go-сервер: `api_key`, `base_url`, `memory_dir`, `read_only`, `audit`
- pi-расширение: `permissions` (политика из того же файла — единая точка контроля)

### Санитизация

- Ключ не логируется, не попадает в ошибки и ответы инструментов никогда
- Дочернему процессу ключ передаётся только через env **конкретного процесса** (стандарт MCP `StdioServerParameters.env`); в транскрипты и общий env не попадает
- `yougile-mcp init` — команда миграции: читает `YOUGILE_API_KEY` из текущего env, пишет config.json с правами 600, выводит инструкцию «удалите переменные из окружения»

### Действия пользователя (после реализации)

1. `yougile-mcp init` (или вручную создать файл)
2. Найти и удалить `YOUGILE_API_KEY`, `YOUGILE_LOGIN`, `YOUGILE_PWD` из окружения (источник не найден в ~/.bashrc, ~/.profile, /etc/environment — проверить менеджер сессий/скрипты запуска pi)
3. **Ротировать ключ** (см. §6) — обязателен из-за инцидента

## 2. Фаза 2 — Аннотации инструментов + read-only режим

### Аннотации (метаданные MCP)

| Инструмент | readOnlyHint | destructiveHint | idempotentHint |
|------------|--------------|-----------------|----------------|
| list_projects, list_boards, list_columns, list_tasks, get_task, get_stickers, get_board_snapshot | true | false | true |
| summarize_board, track_goals | true | false | true |
| create_task | false | true | false |
| update_task | false | true | true |
| bulk_move_tasks, batch_update_stickers | false | true | true |
| audit_board | false | true | false |
| compress_reviews | false | true | false (пишет локальные файлы отчётов) |

### Read-only режим

`"read_only": true` в конфиге → сервер **не регистрирует** мутационные инструменты вообще: их нет в `tools/list`, LLM их не видит. Двойная защита: если инструмент всё же вызван напрямую — хендлер возвращает ошибку `read-only mode`.

## 3. Фаза 3 — Контроль мутаций пользователем (pi-расширение)

### Три уровня политики (glob-паттерны имён инструментов)

| Уровень | Поведение |
|---------|-----------|
| `allow` | вызов проходит без вопросов (чтение) |
| `confirm` | **диалог подтверждения** перед выполнением: tool + аргументы + счётчик затронутых объектов |
| `deny` | инструмент **не регистрируется** — LLM его даже не видит |

Реализация: проверка политики прямо в `execute()` зарегистрированного инструмента (у нас есть `ctx` → `ctx.ui.confirm`). `deny` отсекается на регистрации.

### Dry-run-first для массовых операций

Для `bulk_move_tasks`, `batch_update_stickers`, `audit_board(autoMove=true)`:
1. Расширение сначала вызывает инструмент с `dryRun: true`
2. Показывает результат (что будет изменено, N объектов)
3. Спрашивает `ctx.ui.confirm` («Переместить 23 задачи в Review?»)
4. При согласии — реальный вызов

Отключается в политике (`"bulk_dry_run_first": false`).

### Команда `/yougile-status`

Показывает: режим (read-only?), активную политику (allow/confirm/deny), путь конфига и аудит-лога, версию сервера, число зарегистрированных инструментов.

## 4. Фаза 4 — Аудит мутаций

Файл `~/.local/state/yougile-mcp/audit.jsonl` (append-only, по строке на событие):

```json
{"ts":"2026-08-17T16:20:01Z","tool":"bulk_move_tasks","mode":"normal","outcome":"ok","args":{"targetColumnId":"fae...","count":23}}
{"ts":"2026-08-17T16:22:10Z","tool":"update_task","mode":"read-only-blocked","outcome":"error","args":{"taskId":"60a..."}}
```

- Пишет **сервер** (единая точка прохождения всех мутаций)
- Аргументы пишутся полностью (не содержат секретов); исходы включают блокировки read-only
- Каталог создаётся автоматически (700)

## 5. Итоговая матрица «как пользователь контролирует»

| Механизм | Что контролирует | Где |
|----------|------------------|-----|
| Конфиг-файл (600) | единственное место хранения секрета | `~/.config/yougile-mcp/config.json` |
| `read_only: true` | полный запрет мутаций на уровне сервера | конфиг |
| `permissions.allow/confirm/deny` | какие инструменты доступны LLM и какие требуют подтверждения | конфиг (glob) |
| Диалоги confirm | каждая мутация — явное «да» в UI pi | расширение |
| Dry-run-first | массовые операции сначала показывают план изменений | расширение |
| Аудит-лог | история всех мутаций для разбора | `~/.local/state/yougile-mcp/audit.jsonl` |
| `/yougile-status` | текущее состояние безопасности в сессии pi | команда pi |
| Ротация ключа | восстановление после утечки | §6 |

## 6. Ротация ключа (процедура пользователя)

1. Создать новый ключ: YouGile UI (Профиль → API) или `POST /auth/keys` (login + password, одноразово)
2. Записать в `~/.config/yougile-mcp/config.json`, проверить `chmod 600`
3. Перезапустить pi-сессию
4. Удалить старый ключ: UI или `DELETE /auth/keys/{key}`
5. Убедиться, что старый ключ нигде не остался (grep по env-скриптам)

| Фаза | Работы | Файлы |

### Тесты

- config: загрузка, отказ при неправильных правах, приоритет источников
- read-only: `tools/list` не содержит мутационных инструментов
- аудит: append JSONL, блокировки пишутся
- расширение: glob-матчинг политики (юнит-тесты匹配)

### Правило тестирования E2E (новое)

Мутации в тестах — только с немедленным cleanup или на выделенной тестовой доске; по умолчанию `dryRun`.

## 9. Что НЕ делаем (границы v1)

- OS keyring (secret-service/gnome-keyring) — возможно в v2; файл 600 достаточен для single-user
- Сетевой транспорт (HTTP/SSE) — не открываем
- Аутентификация/авторизация пользователей — вне модели угроз
- Шифрование файла ключа — защищаемся правами ФС
